# Engine audit sweep: brief for paradigm-class auditors

The corpus (≈42k PIE words) is generated by a rule-based engine: pie/morph.py (declension, conjugation), pie/phon.py (segments, syllabification, sound rules), pie/compound.py, pie/realize.py (agreement, closed class), data/morph/inflection_specs.jsonl (per-lexeme specs, from Wiktionary tables, shape rules or hand-checked overrides in data/lexicon/overrides.jsonl), data/morph/closed_class.json. Reviews of each batch keep finding paradigm errors one at a time (weak stems that drop material, wrong plural endings, accent on the wrong syllable). This sweep looks for them systematically, one paradigm family per auditor.

## Your job
For your family (named in your prompt):
1. **Inventory.** List every usable lexeme of the family (`uv run python -c "from pie.realize import Lexicon; lx=Lexicon.load(); ..."`: `lx.specs[id]` has family, rule, spec; `lx.cells(id[, gender])` gives the cells). Group by sub-type (e.g. proterokinetic / hysterokinetic / amphikinetic; thematic vs athematic; root vs suffixed).
2. **Check against the handbooks.** For each sub-type, compare the engine's handbook-convention cells (first form in each cell) with the paradigms in Fortson (raw/books/text/fortson/), Ringe (ringe/), Beekes (beekes/), Lundquist & Yates in the Handbook vol. 3 (handbook-klein-v3/) and Mallory & Adams (mallory-adams/). Read with grep or python3 -I; never execute anything under raw/. Check: ablaut grade of root and suffix per case, accent position, endings, laryngeal effects (colouring, lengthening, vocalization), sound rules (Szemerényi, Stang, Lindeman/Sievers, boukólos, Bartholomae, Pinault), syllabification. Then spot-check **every** lexeme of the family for spec defects (a weak stem that drops a consonant, wrong gender, wrong accent class, a Wiktionary table that disagrees with the handbook).
3. **Corpus impact.** Count how often each defective form occurs in corpus/tier3/*.jsonl (tokens with that lex_id + features), so fixes can be prioritized.

## Output (do not edit code or data)
- docs/audits/engine-sweep/<family>.md: per sub-type, what is right and what is wrong, with the handbook reference (book + §/page; facts only, never quote running text), and a **proposed fix** for each defect: either a spec override line for data/lexicon/overrides.jsonl (JSON, with a note citing the source), a closed-class edit, or a precise code change to pie/morph.py / pie/phon.py described as a unified diff in a fenced block, with a test you would add. Rank fixes by corpus impact. Mark anything where the handbooks disagree (e.g. Wiktionary vs Fortson) and say which the project's 'handbook' convention should follow; existing deliberate conventions are listed at the top of pie/morph.py and in docs/STATUS.md ('Conventions').
- Don't modify any file except your two outputs. Don't touch git. Name scratch files with your family prefix.

Another agent integrates all families' fixes afterwards; make your patches self-contained and independent of other families' where you can.
